# Arkiv + 0G paper diagnostic

Run `pnpm 0g:arkiv-paper` from the repository root. This sends up to six paid 0G calls, with a $0.004 conservative reservation cap, and queries published BTCUSDT market snapshots from Arkiv. It uses existing configured 0G credentials and requires the key to allow `0gm-1.0-35b-a3b` and `qwen3.7-flash`. It does not start the hosted runtime or submit orders. The key's separate spending cap still applies. An ambiguous inference or unknown billing stops the run without retrying and keeps the reservation in the final report.

The experiment compares two model configurations with the same momentum instructions and virtual $1,000 account (500 USDT cash and $500 of BTC at the initial mid-price). It sends one decision request per model for each of three observation intervals. Only observations already published on Arkiv are supplied; a decision can only fill at the next published observation, at least 30 seconds later, using the future bid for sells or ask for buys, with a 0.1% fee. Prices originate from Binance USD-M futures snapshots, while fills are hypothetical spot trades, and USDT is treated as approximately USD. The data are historical snapshots, not necessarily current market prices or executable quotes. There is no modeled slippage, liquidity constraint beyond bid/ask, funding, market impact, gas, or model quality evaluation.

0GM uses 0G's verified-provider route but the response observed in this experiment did not include a verification flag. Qwen3.7 Flash uses standard routing. This isolated diagnostic intentionally displays their outputs despite that difference; neither result is accepted by the hosted execution harness. 0GM's thinking output is disabled for this test, which can affect reasoning quality. This is a direct model comparison, not an end-to-end test of the hosted agent, Flash, risk gate or 0G response attestation.

The runner atomically updates `.perpetua/paper-leaderboard.json` after each completed round; the website's **Paper competition** section polls it every 15 seconds. The usual live leaderboard stays separate. Each run also saves an immutable-by-convention report under `.perpetua/competitions/<run-id>/leaderboard.json`, including source entity keys, decision details, model latencies and costs. The paper leaderboard is the latest run, not a continuous background service. Failed or incomplete experiments are marked and have unavailable profit rather than being presented as a valid ranking.

Two tests cover publication-time spacing and bid/ask fill and fee arithmetic: `pnpm exec tsx --test scripts/lib/arkiv-paper.test.ts`. A short replay cannot establish profitability, trading safety, uptime, model accuracy or which model is better.
