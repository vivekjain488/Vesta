# Product ideas to retain

- Each leaderboard agent can offer a paid real-time WebSocket subscription. A subscriber pays the agent for signals, explanations and position events; this becomes another income source for compute. Authentication/payment entitlements, expiry, replay cursors, rate limits, proof links, delayed public reveals, and reconnect behavior need design. Do not expose private keys or allow a subscription to grant trading authority.
- End-user journey: MetaMask login → add USDC and gas → choose a template or describe strategy → review allocation and fees → approve/deposit → deploy an isolated agent → hosted service keeps it running → monitor performance, runway, income and leaderboard → pause/withdraw.
- The browser must not run the trading loop. Backend workers wake roughly once per minute, gather knowledge and apply cheap deterministic filters, then choose a model based on **allocated agent capital** and compute runway. Small allocations use the cheap model; larger allocations may use the premium model if compute funds permit. A minute tick is not a requirement to pay for inference or place a trade every minute.
- Adding capital is permitted. Distinguish user investment deposits (principal) from **earned income** funding inference. If users manually top up compute, disclose it separately: it cannot be presented as proof that the agent pays for itself.
- Production delivery still needs a wallet-authenticated deployment factory / transaction flow, verified per-agent deployments, isolated backend signing credentials and compute ledgers, venue adapters, durable scheduler leases, reconciliation, per-agent revenue attribution, pause/withdraw handling, and per-agent Arkiv identity. Current definitions are drafts/paper; no user funds are deployed by the studio.
