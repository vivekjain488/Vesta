# Configurable hosted agents

The strategy studio at `/studio` supports MetaMask/injected wallets and the existing optional Privy bridge. One owner can save multiple agents, including duplicate display names: UUIDs identify agents, and the owner wallet is distinct from an eventual trading wallet or operator key. The studio has form controls, natural-language drafting, and an expandable advanced configuration editor. It saves **draft/paper definitions**, not deployed contracts or live trading instructions.

## User flow and implementation boundary

Implemented: connect owner wallet → choose template or describe strategy → review exposure/risk/model preferences → sign exact configuration → save/revise independent agent definitions. The server consumes a five-minute, audience-bound, single-use signing nonce; it verifies an EOA personal signature and optimistic revision before mutation. No private key is sent from the browser. Configurations are public-readable by owner address; this is not a private user-data store. Smart-contract owner signatures/SIWE sessions, distributed rate limiting and multi-process durable authentication remain future work.

Still required for fund-and-deploy: an audited deployment factory/transaction builder, per-agent USDC allocations and ERC-20 approvals, verified registry/contract ownership, backend key provisioning, wallet network checks, pause/withdraw flows, and venue integration. Do not show a configuration save as an on-chain deployment. The existing three-agent local deployment script still supplies the spot demo.

User additions to investment capital are allowed. Record them as principal deposits; manual compute refills must be separated from earned income when demonstrating 0G self-funding.

## Strategies and compilation

`packages/core/src/agent-config.ts` is a strict, versioned data schema. It rejects unknown fields, unsafe leverage, invalid risk/horizon combinations and unsupported markets. Templates: spot momentum, spot range reversion, spot DCA, futures trend and futures range reversion. All use 4h candles. Futures are paper research only; spot configurations are saved drafts, not automatically applied to the legacy env-driven spot runtime. Funding carry remains research because it needs atomic/controlled two-leg execution and hedge reconciliation.

`POST /v1/strategy/compile` uses a verified live 0G provider to draft configuration and reports unsupported requirements. It never evaluates generated code, alters contracts or activates trading. It is disabled until `CONFIG_COMPILER_ENABLED=true`, `ZG_MODE=live`, `ZG_PRIVATE_KEY` and `ZG_PROVIDER_SMALL` are configured. The compiler has its own operator-funded token budget (10k/hour, 50k/day); it must not be claimed as an individual agent paying for inference. Provider initialization may create/fund its ledger. Sim mode returns an explicit unavailable error instead of pretending to interpret prompts. A compiler's disclosure is not proof of semantic equivalence: the owner reviews the strategy before signing.

The parameter group contains a common superset: minScore/minAgreeing apply to spot momentum; breakoutBars to futures trend; rsiOversold to futures range; stopAtr/targetAtr/minRewardRisk to futures proposals. Saved spot settings have no runtime effect until deployment binding is implemented. These template-specific limits are visible in advanced settings; no profitability is established.

## Hosted harness

`agent/src/hosted.ts` runs server-side. Start with `corepack pnpm --filter @perpetua/agent hosted` (or `pnpm hosted` when pnpm is installed). Set `HOSTED_ADAPTER_MODULE` to an **operator-controlled local module** exporting `createTools(definition)` and optionally `createBrain(definition)`. Each adapter must return isolated per-agent account/margin state and, for live inference, a separately budgeted Brain/compute identity. No venue adapter or signing key is accepted from user configuration.

`createTools` returns the `KnowledgeTools` interface in `agent/src/harness.ts`: market bars with source and fetch timestamp, fresh execution data, account state and optional Signature Atlas lookup. Adapter data must come from the intended venue; liquidation price/protection availability must be venue-derived for the proposed side, margin allocation and size. The generic snapshot check does not replace venue-specific margin calculations. Its current interface is deliberately a research preflight, not a live margin authorization.

The supervisor loads approved paper definitions from `.perpetua/definitions`, schedules each independently (60s default), prevents overlapping ticks, replaces workers after configuration revisions, and isolates failures. Logs are appended to `.perpetua/harness-<agent-id>.jsonl`. It is a **single-process** service: durable leases, crash recovery, persisted spend counters, durable intent idempotency and deployment attestation are required before scaling/live execution. Adapter RPCs must have deadlines; an unresponsive adapter must not be allowed to block shutdown indefinitely.

Each paper worker collects market knowledge, uses closed-candle deterministic rules, and optionally asks AI for at most three allow-listed read-only actions (inspect account, query Atlas, evaluate, wait). It obtains fresh quotes/account data after inference before checking observation age, quote age, spread, price/mark drift, costs, stop/target geometry, daily loss, margin, exposure and liquidation buffer. There is **no transaction tool**, execution/fill simulator or PnL claim. A successful preflight is a research proposal only. The configured minHoldSeconds constrains horizon selection; without positions/fills there is no holding-period or exit enforcement. maxSlippageBps is a modeled stressed-cost input, not an exchange order guarantee.

Per-agent capital routing uses **allocated account equity**, not the owner's total wallet balance. Small eligible allocations select the cheap model; >=$5k defaults to premium only if compute runway also supports Thrive. Runway and token budgets may force a downgrade or rules-only monitoring. A one-minute tick does not require an inference every minute: no candidate means no paid reasoning. maxDailySpendOg stops further calls after observed spend reaches the cap; it is not a pre-authorized hard cost ceiling. Unknown/zero settlement cost blocks subsequent AI calls that day. Production requires persistent pre-call cost reservations and accurate provider-subaccount settlement (the current 0G SDK wrapper's main-ledger delta is insufficient). Runtime token caps and treasury caps remain independent controls.
